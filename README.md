# Нейросетевой синтез фазового ДОЭ: 4 изображения на 4 расстояниях

Нейросеть получает **4 изображения 128×128** одного комплекта и за один вызов строит **один фазовый ДОЭ** (PNG 128×128, 8 бит, grayscale; пиксель 0 → −π, 255 → +π). Фазовая маска при освещении лазером (λ = 532 нм, пиксель ПВМС 10 мкм) восстанавливает изображения по расчёту дифракции Френеля одним БПФ на расстояниях **24,1 / 25,3 / 26,5 / 27,7 мм** (i-е изображение — на i-м расстоянии).

## Что запускать жюри

**Основной и единственный режим для первого знакомства — FASTGS-100.** Он уже выбран в Docker по умолчанию: нейросетевой `stage-0` в `channels_last` создаёт начальную фазу, затем выполняются 100 итераций многоплоскостного GS. Не нужно выбирать чекпойнт, число итераций или передавать `--fastgs`.

Остальные режимы сохранены в проекте, но нужны только для сравнений и исследовательских экспериментов — [они описаны ниже](#необязательные-режимы).

### 1. Собрать образ один раз

```bash
docker build -t doe-synth .
```

Перед очной защитой образ собирается заранее. На сцене остаётся только следующая команда.

### 2. Запустить демо одной командой

```bash
docker run --rm -v "$PWD/out:/out" doe-synth
```

Это основной сценарий без скрытой настройки:

| параметр | значение по умолчанию |
|---|---|
| вход | встроенный комплект `/app/data/demo/shapes` |
| метод | `nn_fastgs` |
| итерации GS | `100` |
| веса | `checkpoints/stage0-finetuned.pt` |
| результат | `./out` на компьютере пользователя |

Флаги `--fastgs`, `--steps 100` и `--checkpoint` специально не нужны. Запуск без аргументов и запуск пользовательских изображений используют один и тот же метод.

### 3. Показать результат

| файл в `out/` | что открыть |
|---|---|
| **`doe.png`** | **ДОЭ**: PNG 128×128, 8 бит, grayscale, 0 → −π, 255 → +π |
| `recon_1.png … recon_4.png` | четыре восстановления по Френелю из сохранённого DOE: амплитуда \|K\|, нормировка на максимум |
| `metrics.json` | SSIM и Pearson по каждой плоскости, средние/худшие значения, время, `"method": "nn_fastgs"`, `"steps": 100` |

Для живого показа достаточно входного комплекта, одной команды, четырёх восстановлений и `metrics.json`. Сборку образа и переключение режимов показывать не требуется.

### Свои 4 изображения — тот же режим, без дополнительных флагов

Положите в папку `in/` ровно четыре PNG (128×128, 8 бит, 1 канал). Порядок — по алфавиту имён: `1.png … 4.png` ↔ 24,1 … 27,7 мм:

```bash
docker run --rm -v "$PWD/in:/in" -v "$PWD/out:/out" doe-synth --in-dir /in --out /out
```

Можно передать файлы явно: `docker run --rm -v "$PWD:/data" doe-synth /data/a.png /data/b.png /data/c.png /data/d.png --out /data/out`.

### Необязательные режимы

Все режимы остаются доступны через тот же образ. Для первого запуска жюри они не нужны.

| режим | команда/флаг | назначение |
|---|---|---|
| **FASTGS-100 — основной** | ничего не добавлять | stage-0 + GS-100; около **150 мс**, SSIM **0,4516**, Pearson **0,6781** на 12 демо |
| FASTGS-50 — запасной скоростной | `--fastgs --steps 50` | около **98 мс**, SSIM **0,4444**; меньше времени, немного ниже качество |
| Прежняя полная сеть | `--fast` | один прямой проход без GS; используется для сравнения с исходной моделью |
| Refine | `--refine` | полная сеть + 100 шагов Adam-уточнения |
| Quality | `--quality` | исследовательский режим отбора по метрикам с дополнительными шагами; занимает секунды |
| Visual | `--visual` | исследовательский multiscale L1 + excess-TV; занимает секунды и не относится к speed benchmark |

`--fastgs` — честный гибрид: нейросеть строит инициализирующую фазу, затем выполняется GS-уточнение. В Docker на 12 демо медиана трёх production-замеров FASTGS-100 около **150 мс**, SSIM **0,4516**, Pearson **0,6781**; GS-200 на тех же данных — около **202 мс**, SSIM **0,4546**, Pearson **0,6825**. Исходный одиночный проход полной сети — около **389 мс**, SSIM **0,3919**. Время зависит от нагрузки: в одной серии был выброс до 264 мс, поэтому показываем медиану повторов, а не лучший запуск. Обычный GS-50 всё ещё быстрее (~51 мс, SSIM **0,4401**), поэтому преимущество не формулируется как победа над любым классическим методом при любом числе итераций. Числа из разных режимов и наборов нельзя смешивать в один benchmark.

Без Docker: `pip install -r requirements.txt && DOE_DEFAULT_MODE=fastgs python predict.py --in-dir in --out out`. Время и качество подробнее — ниже.

## Как это устроено

- `doe/physics.py` — Френель одним БПФ: `K = FFT(H·exp(jπ(u²+v²)/λz))` (центрированная сетка, унитарное БПФ; внешние множители не влияют на амплитуду после нормировки). NumPy-версия для оценки и дифференцируемая PyTorch-версия для обучения.
- `doe/model.py` — U-Net в плоскости ДОЭ (11,8 млн параметров) + **6 обучаемых стадий уточнения** (обучаемый аналог Gerchberg–Saxton; всего 15,4 млн параметров). Вход сети: 4 изображения и они же, точно распространённые назад в плоскость ДОЭ.
- `doe/losses.py` — обучение **без учителя**: фаза → расчёт Френеля → сравнение с целями **теми же метриками, что у жюри** (Pearson, SSIM; амплитуда |K|, каждое изображение нормируется на свой максимум) + **штраф за перекрёстные помехи**, который не даёт сети выдавать одну и ту же «смесь» всех 4 картинок во всех плоскостях.
- Обучение: `doe/train.py`, `colab/train_colab.ipynb` (Google Colab, L4). Три этапа: база → со штрафом за помехи → 6 стадий. Веса: **`checkpoints/best.pt`** (отбор по валидации).
- Данные для обучения: генератор `doe/data.py` — шрифты, фигуры, логотипы + открытые наборы (Caltech-101/256, Oxford Flowers-102, DTD, BSDS500, Fashion-MNIST); источники и лицензии — `data/SOURCES.md`. Разделение train/val/test **по источникам** (классам объектов и шрифтам), а не по аугментациям.
- `evaluate.py` — независимая проверка по одному `doe.png` (без нейросети и torch): повторяет расчёт Френеля и метрики.

```bash
python evaluate.py out/doe.png t1.png t2.png t3.png t4.png     # метрики из сохранённого PNG ДОЭ
```

## Протокол оценки, который мы считаем (по ответам экспертов)

Сравниваются **амплитуды |K|**, каждое изображение (исходное и восстановленное) нормируется так, что максимум = 1; Pearson и SSIM считаются по каждой плоскости и усредняются. SSIM: формула слайда (глобальная, `ssim_global`); дополнительно считаем оконные варианты (skimage 7×7, гауссово 11×11), так как реализация жюри неизвестна. Метрики считаются по **перечитанному 8-битному PNG** ДОЭ.

## Результаты (TEST: 256 комплектов с классами объектов и шрифтами, не встречавшимися при обучении; среднее и 95% bootstrap-ДИ)

| режим | SSIM (слайд, глоб.) | SSIM skimage 7×7 | SSIM gauss 11×11 | Pearson ср. | Pearson худш. плоск. |
|---|---|---|---|---|---|
| быстрый: сеть, 1 проход | 0,342 [0,331; 0,353] | 0,192 | 0,192 | 0,511 [0,501; 0,522] | 0,442 |
| сеть + 100 шагов (`--refine`) | **0,433 [0,421; 0,444]** | **0,299** | **0,304** | **0,560 [0,550; 0,569]** | **0,478** |
| GS-200 (классика, для сравнения) | 0,375 [0,362; 0,388] | 0,210 | 0,210 | 0,544 [0,531; 0,557] | 0,291 |

Время на один комплект зависит от устройства и реализации. Сопоставимый замер сети и GS-200 на этом Mac приведён выше; времена уточнения и метрики приведены в `results/jury_quality/report.md`.

Что важно: изображения **не безупречны** — в каждой плоскости есть зернистость (спекл) и слабые следы соседних изображений. Мы не рассматриваем текущий результат как доказанный физический предел для одной фазовой маски 128×128: это достигнутый нашими методами компромисс между сходством, спеклом и разделением плоскостей. Сложность разделения измеряем отдельно («селективность по глубине» — разность корреляции с «своей» и «чужими» целями): у режима `--refine` 0,26, у GS-200 — 0,20.

Все цифры воспроизводятся скриптами из `results/` и `scripts/` (подробности — `PLAN.md`, `BACKLOG.md`, `results/ml/summary.md`).

## Эксперимент с качеством (7 ноября 2026)

Добавлен опциональный `--quality`: исходная сеть и 100 шагов уточнения, затем
до 300 дополнительных шагов с плавным уменьшением learning rate и отбором
кандидатов по метрикам **сохранённой 8-битной фазы**. Пример запуска режима качества:

```bash
docker build -t doe-synth-jury .
docker run --rm -e OMP_NUM_THREADS=4 -v "$PWD/out:/out" doe-synth-jury \
  --in-dir /app/data/demo/shapes --out /out/quality --quality --figure
```

Для своих изображений дополнительно смонтируйте `-v "$PWD/in:/in:ro"` и укажите
`--in-dir /in`. С `--quality --steps N` параметр N означает **дополнительные**
шаги после базовых 100. `--fast`, `--refine` и `--quality` взаимоисключающие.
`--checkpoint PATH` позволяет явно выбрать другие веса.

На 64 отложенных комплектах: Pearson **0,5702 → 0,5773**, глобальный SSIM
**0,4208 → 0,4287**, Gaussian SSIM **0,3002 → 0,3198**. Выбор настроек сделан
на отдельных 32 валидационных комплектах. Это новые комбинации изображений из
источников, ранее использованных проектом; результаты не заменяют внешнюю
проверку на наборе жюри. Более высокое качество требует дополнительного времени.

При отборе средние Pearson и три SSIM не могут ухудшиться относительно базового
ДОЭ на том же входе. Допуски для худшего Pearson и селективности — 0,01 и 0,02.
Прокси выбора `0.4*Pearson + 0.3*SSIM_global + 0.3*SSIM_gauss` — инженерный
критерий для сочетания метрик и визуального качества, не формула балла жюри.

Отдельно выполнено пилотное дообучение на 400 шагов. Оно улучшило метрики чистой
сети, но снизило разделение по глубине; исходные веса остаются стандартными.
Новые веса локально: `out/jury/checkpoints/jury_pilot/best.pt`. Для запуска в Docker
при монтировании `out:/out` используйте
`--checkpoint /out/jury/checkpoints/jury_pilot/best.pt --fast` вместе с входными
изображениями и папкой результата. Эти экспериментальные веса не входят в Git.

Полный протокол, ограничения, результаты дообучения и команды воспроизведения:
[results/jury_quality/report.md](results/jury_quality/report.md).
Локальная галерея после эксперимента: `out/jury/gallery/index.html`.

## Эксперимент visual и teacher→student (8 ноября 2026)

Запуск визуального режима:

```bash
python predict.py --in-dir data/demo/shapes --out out/visual --visual --figure
```

`--visual` использует `doe/perceptual.py`: базовые 100 шагов, затем multiscale L1
с весом 0,3 и штраф только на избыточную относительно цели зернистость excess-TV
с весом 0,1. Кандидаты квантуются и проходят те же ограничения по метрикам, что и
в `--quality`; постобработки восстановленных PNG нет. `--steps N` задаёт число
дополнительных шагов после базовых 100. Это отдельный режим, а не замена `--quality`.

На четырёх исследовательских демо (`rocket_smoke`, `shapes`, `halftone_photos`,
`photo_text`; это не отложенный внешний тест) вариант MS-L1 + excess-TV дал Pearson
**0,6422** против **0,6408** у quality, глобальный SSIM **0,5415** против **0,5381**,
background RMSE **0,1923** против **0,1986** (уменьшение примерно на 3,2%). Gaussian
SSIM был **0,3518** против **0,3534**, то есть универсального выигрыша по всем метрикам
нет. Полный CLI на shapes дал Pearson **0,6796**, глобальный SSIM **0,5472**,
селективность **0,258**, синтез около **1,68 с** на MPS.

Также созданы 512 teacher-комплектов и проведены эксперименты дистилляции в компактный
student. Ни student с нуля (2,52 млн параметров), ни усечённые 2-стадийные веса не прошли
заранее заданные пороги качества/селективности, поэтому чекпойнты student не принимаются
и стандартная модель не меняется. Обрезка без дообучения показала компромисс: 2 стадии —
3,15× ускорение против GS-200 на MPS при Pearson 0,419; 4 стадии — 2,19× при Pearson
0,483; полная сеть — 0,501 на той же выборке. Эти числа не подтверждают ускорение 5× с
сохранением качества. Подробности и отрицательные результаты сохранены в исследовательском
отчёте рабочей области.

## Основной Docker-режим fastgs (8 ноября 2026)

Обычный запуск `docker run --rm -v "$PWD/out:/out" doe-synth` теперь вызывает
`--fastgs` автоматически. Для своих изображений используется та же команда с
`--in-dir /in --out /out`. Число итераций меняется явно:

```bash
docker run --rm -e OMP_NUM_THREADS=4 -v "$PWD/in:/in" -v "$PWD/out:/out" \
  doe-synth --in-dir /in --out /out --fastgs --steps 50
```

Веса `checkpoints/stage0-finetuned.pt` содержат наследованную первую стадию существующей
дообученной модели, без шести стадий уточнения. Это не новый student: неудачные
student-эксперименты выше не используются. В CPU Docker включён `channels_last`,
а GS-старт от массива фазы проверен отдельным регрессионным тестом.

Проверка production-пути на всех 12 демо:

```bash
docker run --rm --entrypoint python -e OMP_NUM_THREADS=4 \
  -v "$PWD/out:/out" doe-synth -m scripts.verify_fastgs_demos --steps 100 --out /out
```

Полный холодный запуск контейнера на shapes занял **2,17 с** со всеми накладными
расходами; внутри программы синтез занял **192 мс**, весь pipeline — **350 мс**.
Средние метрики по 12 демо и три повтора скорости сохраняются в `research/`
рабочей области; подробный отчёт и Pareto-график — в `docs/PHOTONICS_SPEED_DEFENSE.md`.
