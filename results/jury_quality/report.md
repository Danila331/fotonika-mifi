- На валидации сравнили только три заранее заданных конфигурации: balanced, global emphasis, peak finish. Победитель зафиксирован в `frozen.json` до оценки теста. Затем один полный тестовый прогон пяти режимов. Изменения после него касались отчётности и проверок, а не параметров модели/оптимизации.

- Bootstrap: 4000 парных перевыборок комплектов, seed 791903. ДИ относится к этой выборке и не учитывает все источники неопределённости, включая случайность обучения.

## Как устроен quality

Сначала выполняется штатная сеть + 100 шагов. Затем ещё до 300 шагов Adam: alpha=1, beta=0.5, xtalk=0.25, learning rate плавно уменьшается от 0.03 к 0.003. Каждые 50 шагов кандидат квантуется по штатному кодеку, восстанавливается и оценивается. Базовый кандидат всегда доступен.

Кандидат допускается, только если средние Pearson, глобальный SSIM, SSIM 7×7 и Gaussian SSIM не хуже базы. Худший Pearson может снизиться не более чем на 0.01, селективность не более чем на 0.02. Среди допустимых вариантов выбирается максимум `0.4*Pearson + 0.3*SSIM_global + 0.3*SSIM_gauss`. При неопределённом Pearson оставшиеся веса нормируются. Это инженерный прокси, не официальная формула балла.

## Условия задачи и ограничения

Проверены предоставленные пользователем «AI фотоника.pdf» (слайды 2, 3, 5, 6) и «Хакатон_задача_q2.docx». Требуются нейросетевой метод, один фазовый ДОЭ 128×128, PNG L 8 бит, диапазон −π…π, восстановление модулей поля по заданному одно-БПФ оператору Френеля. Физические параметры совпадают с кодом.

Документы не задают итоговую формулу ранжирования, численные константы SSIM, лимит времени или явное разрешение итеративного уточнения после сети. В материалах для жюри следует явно различать чистую сеть и гибридный quality-режим. Peak-нормировка и константы SSIM сохранены из существующего протокола проекта; реализацию жюри отдельно подтвердить не удалось.

## Воспроизведение

Данные источников: [Caltech-101](https://data.caltech.edu/records/mzrjq-6wc02), [BSDS500](https://www2.eecs.berkeley.edu/Research/Projects/CS/vision/grouping/resources.html). Архивы `caltech-101.zip`, `BSR_bsds500.tgz` помещаются в `data/external/_downloads/`.

```bash
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r requirements.txt pytest
.venv/bin/python -I scripts/prepare_external.py --only c101 bsds --workers 4
# На свежем checkout: prepare отказывается перезаписывать уже подготовленный эксперимент.
.venv/bin/python scripts/jury_experiment.py prepare
.venv/bin/python scripts/jury_experiment.py validate
.venv/bin/python -m doe.train --run jury_pilot --init checkpoints/best.pt --device mps --steps 400 --batch 2 --workers 0 --lr 0.00001 --warmup 20 --alpha 1 --beta 0.5 --xtalk 0.25 --soft-beta 20 --quant --val-n 32 --val-every 100 --save-every 400 --best-metric J --seed 791904 --ckpt-dir out/jury/checkpoints --results-dir out/jury/training
.venv/bin/python scripts/jury_experiment.py finetune --checkpoint out/jury/checkpoints/jury_pilot/best.pt
.venv/bin/python scripts/jury_experiment.py test
.venv/bin/python scripts/jury_experiment.py gallery
```

Точные версии окружения: `out/jury/requirements-lock.txt`. Побитовая повторяемость между CPU и MPS не обещается. Тестовые массивы следует использовать сохранённые, поскольку набор системных шрифтов влияет на генератор. Повторная оценка теста после подбора по его результатам требует нового внешнего набора.
